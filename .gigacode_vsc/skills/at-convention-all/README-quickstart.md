# Проектная разведка тестового проекта — QuickStart

## Что это?

**at-convention-all** — универсальный скилл, который собирает **«проектную разведку»**
для **любого** тестового проекта: автоматически определяет фреймворк (Playwright / Cypress /
Jest / Vitest и др.), анализирует код и формирует структурированный Markdown-отчёт с фактами
и конвенциями. Этот отчёт затем использует другой агент для генерации **корректных** автотестов.

Отчёт сохраняется в файл `<имя-проекта>-project-intelligence.md`.

### Ключевое отличие от старого скилла

Скилл **не привязан к конкретному продукту** и не навязывает жёстких правил из одного проекта
(например, «второй аргумент `expect` обязан быть на русском»). Вместо этого он **обнаруживает**
фреймворк и собирает то, что реально есть в коде, помечая отсутствующие паттерны как
«Не обнаружено».

---

## Установка

Скилл лежит по пути:

```
<проект>/.gigacode/skills/at-convention-all/
```

Внутри:
- `SKILL.md` — описание и алгоритм работы;
- `references/` — справочники (детекция фреймворков, шаблон отчёта, техника сбора);
- `README-quickstart.md` — этот файл.

Запуск — командой `/skill at-convention-all`.

---

## Быстрый запуск

```bash
# 1. Запусти скилл в чате
/skill at-convention-all

# 2. Укажи путь к тестовому проекту
#    Нажми Enter — будет использован текущий каталог
#    Или укажи полный путь

# 3. Результат:
✅ Файл <имя>-project-intelligence.md создан
```

## Что анализируется

| Область | Что смотрит |
|---|---|
| Фреймворк | Автоопределение: Playwright / Cypress / Jest / Vitest и др. (по конфигам и `package.json`) |
| Конфиги | `package.json`, конфиги фреймворка, `tsconfig.json`, линт-конфиги |
| Структура | Где живут тесты, утилиты, Page Objects, фикстуры, setup/auth |
| Тесты | Выборка 5–8 модулей из разных доменов — импорты, паттерны, локаторы, ассерты |
| Конвенции | Именование, стиль, фикстуры, хуки, таймауты, тестовые данные, теги |
| Инфраструктура | CI/CD, артефакты и отчёты, setup и аутентификация |

---

## Формат результата

Файл `*-project-intelligence.md` содержит до 19 разделов:

```
## 1. Мета и версии
## 2. Тестовый фреймворк и конфиги
## 3. Структура проекта
...
## 19. Полезные выводы для генератора
```

Каждый раздел — примеры только из реального кода (с путём). Пустые разделы помечаются
«Не обнаружено».

## Пример структуры на выходе

Ниже — как выглядит сформированный отчёт `*.project-intelligence.md` на примере условного
проекта **my-app**. Заполнение каждого раздела пояснено. Реальные пути и примеры в отчёте
будут отличаться — они берутся из конкретного анализируемого проекта.

```text
# Project Intelligence — my-app

## 1. Мета и версии

| Параметр | Значение |
|---|---|
| Название | my-app |
| Версия | 1.2.0 |
| Фреймворк | Playwright |
| Версия фреймворка | 1.48.0 |
```

> Пояснение к разделу 1: заполняется из `package.json` (поле `name`/`version`) и версии
> тестового пакета. Фреймворк определяется автоматически по конфигу и зависимостям.

### 2. Тестовый фреймворк и конфиги

```text
| Настройка | Значение |
|---|---|
| baseURL   | https://example.com |
| timeout   | 30_000 |
| retries   | 1 |
| reporter  | html, list |
```

```typescript
// playwright.config.ts (фрагмент)
export default defineConfig({
  timeout: 30_000,
  retries: 1,
  reporter: [['html'], ['list']],
});
```

> Пояснение к разделу 2: ключевые настройки конфига + цитата реального кода.
> Числовые значения, адреса и пути в отчёте — фактические, из анализируемого проекта.

### 3. Структура проекта

```text
my-app/
├── tests/
│   └── login.spec.ts
├── utils/
│   └── api.ts
└── .auth/
```

> Пояснение к разделу 3: ASCII-дерево, показывающее, где живут тесты, утилиты,
> фикстуры, setup/auth.

```text
# Далее разделы 4–19 формируются по той же логике:
# 4.  Запуск и скрипты        — команды из package.json
# 5.  Правила именования      — паттерны тест-файлов и классов
# 6.  Стиль кода и линт       — eslint/tsconfig и порядок импортов
# 7.  Локаторы/селекторы      — таблица типов локаторов с количеством использований
# 8.  Page Object Model       — есть ли классы Page / атомарные функции
# 9.  Фикстуры                — test.use, base.extend, кастомные фикстуры
# 10. Ассерты                 — частые матчеры и мягкие проверки
# 11. Таймауты и ожидания     — waitFor*, константы таймаутов
# 12. Тестовые данные         — faker, генераторы, моки
# 13. Хуки                    — beforeEach/All, afterEach/All
# 14. Setup и аутентификация  — .auth, storageState, env-флаги
# 15. Теги и маркировка       — tag, describe.only/skip
# 16. CI/CD                   — .github/workflows, .gitlab-ci.yml
# 17. Артефакты и отчёты      — reporter, screenshot/video/trace, allure
# 18. Эталонный тест          — 1–2 крупнейших теста из разных доменов с цитатами
# 19. Полезные выводы        — правила для генерации автотестов (что использовать/избегать)
```

> Пояснение: разделы с 4 по 19 наполняются реальными фактами из кода. Если какой-то
> паттерн в проекте отсутствует (например, нет CI-конфигов или POM), в разделе пишется
> «Не обнаружено» — без шаблонных заглушек.


## Требования

- **Язык** → русский (если проект русскоязычный)
- **Факты** → только из кода проекта (ничего не выдумывать)
- **«Не обнаружено»** → если паттерн отсутствует, не подставлять шаблон
- **Без привязок** → не искать пути/теги/правила из конкретного продукта
- **Не менять код** → скилл только создаёт новый файл отчёта

## Команды для быстрой проверки после генерации

```bash
# Посмотреть структуру тестов
dir /s /b src\tests\ 2>nul | findstr /v node_modules

# Проверить конфиг фреймворка
type playwright.config.ts

# Определить фреймворк по зависимостям
findstr /i "playwright cypress jest vitest" package.json
```
